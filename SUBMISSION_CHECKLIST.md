# Gujarat Prahari AI - Submission Checklist

## Form upload mapping

Upload each local artifact to one shared Google Drive folder and set access to
"Anyone with the link - Viewer" before pasting its URL into the form.

1. **Solution Presentation Link** - `Gujarat_Prahari_AI_Hackathon_Submission.pptx`
2. **High-Level Design / Architecture Document Link** - `Gujarat_Prahari_AI_High_Level_Design.pdf`

4. **Screenshots Folder Link** - `Gujarat_Prahari_AI_Screenshots/`
5. **Solution Video Link** - record and upload a 3-5 minute MP4 using the script below
6. **Any other document or video** - GitHub repository and live dashboard links

## Mandatory demonstration sequence

1. Show the live dashboard and repository commit.
2. Connect a laptop webcam, phone IP-camera stream, or authorised RTSP feed.
3. Demonstrate people/vehicle detection and stable ByteTrack IDs.
4. Trigger a restricted-zone loitering or sudden-crowd alert.
5. Show the representative camera registry, watchlist and event-history APIs.
6. If ANPR has been validated, show a plate read, watchlist match and timestamped
   appearances across cameras. Do not substitute manual/mock events for this step.
7. Explain the edge-to-command-centre architecture and human-verification boundary.

## Suggested 3-5 minute narration

- **0:00-0:25:** Problem - heterogeneous feeds and limited operator attention.
- **0:25-0:55:** Gujarat Prahari AI overview and hybrid edge-first design.
- **0:55-2:15:** Live feed, detection, tracking, zone/crowd alert and event history.
- **2:15-3:10:** Watchlist/API correlation and designated-vehicle workflow.
- **3:10-3:45:** Security, privacy, human verification and 80,000-camera scale path.
- **3:45-4:00:** GitHub, live dashboard and controlled-evaluation next step.

## Before pressing Submit

- Confirm every Drive link opens in a private/incognito browser without login.
- Confirm the video plays at 1080p and code text is readable.
- Keep RTSP usernames/passwords out of the video, PPT and repository.
- Run once on the official provided data before the deadline.
- Report measured FPS, latency and test results; do not invent performance numbers.
- Clearly label representative watchlist data and prototype limitations.
